# Как пишутся логи (частоты и смысл файлов)

Сценарий `scenarios/leader_forward_back.py`.

## 1. `logs/two_drones_log_<run-id>_follower_<N>.csv` (цикл фолловера)

- **Когда:** на **каждой** итерации `follower_loop` (после чтения позиций и перед `move_towards_with_pid`).
- **Частота:** задаётся `--control-hz` (по умолчанию **50 Гц**) → период `sleep` ≈ **20 ms** между итерациями. Если `--control-hz 0`, цикл без `sleep` — частота не ограничена (может быть выше).
- **Содержимое:** `t`, `leader_x/y` (из `get_other_drones_positions`, обновляются в потоке обмена), `follower_x/y`, ошибки, скорости, `loop_dt`.
- **Нюанс:** координаты лидера в этом файле могут **повторяться** несколько строк подряд (лидер обновляется в другом потоке), затем **скачок** — для реплея лучше `*_exchange_sync.csv`.

## 2. `logs/two_drones_log_<run-id>_exchange_sync.csv` (синхронная пара)

- **Когда:** **одна строка на тик** `coordinate_exchange_loop`, сразу после рассылки позиций между дронами.
- **Частота:** `--exchange-hz` (по умолчанию **50 Гц**, период ≈ **20 ms**). `--exchange-hz 0` — без ограничения периода цикла.
- **Содержимое:** лидер и фолловер из **одного снимка** `positions` (общий NED-кадр) — оптимально для конвертации в эксперимент и RViz.

## 3. `experiments/.../drone_<id>.csv` (эксперимент)

- **Когда:** в том же `coordinate_exchange_loop`, но строка пишется **только если** изменился кортеж `(x, y, z, rx, ry, rz)` и выполняется `--log-hz` (если задан).
- **Частота:** не фиксирована: зависит от **изменения состояния** и SITL; у разных дронов **разные** моменты записи → при реплее нужно выравнивание времени (см. `replay/csv_loader.py`, `align="t"`).

## 4. `experiments/.../position_errors.csv`

- **Когда:** каждый тик обмена (как цикл обмена).
- **Частота:** как **`--exchange-hz`**.

---

Итого для оценки «как в логе идёт время»: для равномерной сетки смотрите **`exchange_sync`** или **`follower_*`**; для «только при изменении позы» — **`drone_*.csv`**.
