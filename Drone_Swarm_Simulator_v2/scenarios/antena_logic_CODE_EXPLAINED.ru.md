# Построчное и пофункционное описание `antena_logic.py`

Документ описывает файл сценария вертикальной «антенны» из дронов: назначение модулей, констант, каждой функции и логику по блокам с привязкой к номерам строк исходника.

---

## 1. Назначение модуля (строки 1–13)

| Строки | Содержание |
|--------|------------|
| 1–13 | Докстринг модуля: сценарий для 4 дронов (концептуально), выстраивание в вертикальную колонну над «якорем» по локальному правилу ближайших соседей по высоте, без привязки ID к слоям. Отсылки к KA008 / `grid_antenna`. Управление: RC override — roll/pitch для удержания (x,y) якоря, throttle — bang-bang по скаляру `sigma` (распределение по высоте). |

## 3. Глобальные переменные и константы (40–95)

| Строки | Имя / блок | Назначение |
|--------|------------|------------|
| 40–41 | `START_TIME`, `STOP_EVENT` | Глобальное время старта контроля (для `duration` и относительного времени в логах); событие остановки для потока обмена позициями. |
| 43 | `TAKEOFF_ALT_M` | Целевая высота якоря над землёй (м), для ПИД удержания высоты якоря. |
| 46 | `_HOME_Y_OFFSET_STEP_M` | Шаг смещения по Y в «общей» СК (м) на единицу `id-1`, чтобы совместить разнесённые по Y home SITL в одну логическую плоскость. |
| 49–50 | `CONTROL_HZ`, `CONTROL_DT` | Частота цикла RC-управления (20 Гц) и период шага ПИД/сон. |
| 53–54 | `XY_OUTPUT_LIMIT`, `XY_DEADBAND_M` | Лимит выхода ПИД по roll/pitch (PWM-единицы от нейтрали) и мёртвая зона ошибки позиции по XY (м). |
| 57–61 | `W_SPACING_M`, `R_VIS_ALT_M`, `XY_VIS_M` | Желаемый вертикальный шаг между «соседями»; радиус видимости по высоте; горизонтальный порог «видимости» соседа (большой — фактически отключить гейтинг по XY). |
| 64–65 | `Z_PWM_MAX`, `Z_PWM_MIN_STEP` | Макс. приращение throttle от нейтрали и минимальный шаг при ненулевом `sigma` (bang-bang с насыщением). |
| 67 | `ANCHOR_Z_PID_OUTPUT_LIMIT` | Лимит выхода ПИД высоты для якоря. |
| 70 | `POST_CONNECT_SETTLE_SEC` | Пауза после подключения MAVLink до `initialize`, чтобы барометр/EKF успели до ARM. |
| 72–95 | `INIT_STEPS` | Последовательность шагов инициализации: GUIDED → arm → взлёт 5 м → POSHOLD (дважды) → RC override нейтраль → комментарии про частоту позиции через `.parm`. |

## 4. Вспомогательные функции позиции и RC (98–117)

### `_did_offset_y(did: int) -> float` (98–99)

- Возвращает смещение по Y для дрона с целочисленным `id`: `(id - 1) * _HOME_Y_OFFSET_STEP_M`.
- Нужно, чтобы в общей СК координаты разных инстансов SITL совпали по задумке сценария.

### `_pos_common(controller) -> Dict[str, float]` (102–105)

- Берёт `get_my_position()` у контроллера, читает `id` из `config`.
- Возвращает словарь позиции с полем `y`, к которому прибавлено `_did_offset_y(did)` — позиция в «общем» NED.

### `_altitude_m(pos_common) -> float` (108–110)

- В NED ось Z направлена вниз; высота «вверх» = минус Z.
- Возвращает `-z` в метрах.

### `_clamp_rc(pwm, lo=1100, hi=1900) -> int` (113–114)

- Ограничивает PWM целым числом в диапазоне `[lo, hi]` (типичный диапазон RC).

### `_deadband(x, band) -> float` (117–118)

- Если `|x| < band`, возвращает 0, иначе `x` — подавление дрожания у нуля.

## 5. Математика распределения по высоте (121–197)

### `_xi(g) -> float` (121–122)

- Нелинейность `tanh(g)` — сглаживание расстояний в законе типа KA008.

### `_nearest_above_below_alt(my_pos, peer_positions, *, r_vis_alt_m, xy_vis_m)` (125–160)

**Назначение:** для текущего дрона найти расстояния по вертикали до ближайшего соседа **выше** и **ниже** по высоте среди пиров в горизонтальном радиусе `xy_vis_m` и с разницей высоты `< r_vis_alt_m`.

**Построчно внутри:**

| Строки | Логика |
|--------|--------|
| 138–140 | Своё `my_alt`, `mx`, `my`. Инициализация `d_plus`, `d_minus` как `None`. |
| 143–160 | Цикл по `peer_positions`: проверка дистанции в XY; если вне `xy_vis_m` — `continue`. `da` — разница высот пира и себя; если `|da| >= r_vis` или почти ноль — пропуск. Если `da > 0` — сосед выше, обновить минимальное `d_plus`; иначе — сосед ниже, минимальное `d_minus`. |
| 160 | Возврат `(d_plus, d_minus)` в метрах или `None`, если соседа нет в нужном направлении. |

### `_sigma_altitude(d_plus, d_minus, *, w, r_vis, v_alt) -> float` (163–180)

**Формула:** `sigma = v_alt - xi(d_plus_eff) + xi(d_minus_eff)`, где при отсутствии соседа сверху `d_plus_eff = r_vis`, снизу — `d_minus_eff = w` (якорь/нижняя граница решётки).

| Строки | Логика |
|--------|--------|
| 178–179 | Подстановка эффективных расстояний. |
| 180 | Возврат скаляра `sigma` для закона throttle. |

### `_pwm_from_sigma(sigma, pwm_max, pwm_min_step) -> int` (183–197)

**Назначение:** перевести `sigma` в **дельту** PWM throttle относительно нейтрали (bang-bang по знаку с масштабом по `|sigma|`).

| Строки | Логика |
|--------|--------|
| 189–191 | Малый `sigma` → дельта 0. |
| 192 | Направление: `u = -sign(sigma)` в виде `direction` (вверх по высоте — увеличение throttle при нужной полярности ошибки). |
| 193–196 | `mag` ограничен 1; `delta` пропорционален `pwm_max * mag`, не меньше `pwm_min_step`. |
| 197 | Возврат целой дельты PWM (знак × величина). |

## 6. ПИД-регуляторы (200–229)

### `_pid_xy() -> Tuple[PIDRegulator, PIDRegulator]` (200–217)

- Создаёт два `PIDRegulator` для **pitch** (по ошибке по X) и **roll** (по ошибке по Y) с коэффициентами из констант; лимит выхода `XY_OUTPUT_LIMIT`.
- В цикле управления: ошибка X → pitch, ошибка Y → roll (см. знаки в `_control_loop`).

### `_pid_anchor_z() -> PIDRegulator` (220–229)

- Один ПИД для **якоря**: ошибка высоты → дельта throttle; `output_limit = ANCHOR_Z_PID_OUTPUT_LIMIT`.

## 7. Инициализация дрона в потоке (232–277)

### `initialize_drone_parallel(controller, init_barrier, *, heartbeat_timeout_s, position_timeout_s=10.0, barrier_timeout_sec=60.0) -> None` (232–277)

**Назначение:** подключение MAVLink, пауза для стабилизации сенсоров, выполнение `INIT_STEPS`, keepalive RC, ожидание позиции, синхронизация всех дронов через `threading.Barrier`.

| Блок строк | Логика |
|------------|--------|
| 241–245 | `stagger_s` — небольшая задержка по `id`, чтобы разнести подключения. |
| 246–254 | Либо `connect_with_heartbeat_timeout`, либо `connect()`. |
| 256 | Фиксированная пауза `POST_CONNECT_SETTLE_SEC`. |
| 257–260 | `initialize(INIT_STEPS)`; при неуспехе — `TimeoutError`. |
| 261 | `start_rc_keepalive()` — поддержание RC override активным. |
| 263–269 | До `position_timeout_s` ждать появления позиции (`get_position()`), иначе ошибка. |
| 271 | `init_barrier.wait` — ждать остальных участников барьера. |
| 272–277 | При любом исключении: попытка `init_barrier.abort()`, лог `exception`, проброс не делается явно (функция «глотает» и ломает барьер для остальных). |

## 8. Остановка и основной цикл управления (280–374)

### `_stop_all(controllers) -> None` (280–285)

- Для каждого контроллера вызывает `stop()` в `try/except`, чтобы остановить один даже при ошибке другого.

### `_control_loop(controller, *, anchor_id, duration_s, w_spacing_m, r_vis_alt_m, xy_vis_m, z_pwm_max, z_pwm_min_step) -> None` (288–374)

**Назначение:** пер-поточный цикл на 20 Гц: удержание над якорем по XY; для якоря — ПИД по высоте на `TAKEOFF_ALT_M`; для остальных — закон `sigma` и throttle.

| Строки | Логика |
|--------|--------|
| 299–300 | `did` — ID дрона; без `worker` — выход. |
| 304–305 | ПИД XY для всех; ПИД Z только у якоря. |
| 307–309 | Бесконечный цикл; если `duration_s > 0` и время с `START_TIME` вышло — `return`. |
| 311 | `my_pos` в общей СК. |
| 313–320 | Позиции других; позиция якоря; если якоря нет — нейтральный RC, `sleep`, `continue`. |
| 322–328 | Ошибки XY к якорю с deadband; pitch от ошибки по X, roll от ошибки по Y; кламп PWM. |
| 331–341 | Если этот дрон — якорь: ошибка высоты к `TAKEOFF_ALT_M`, ПИД → throttle, отправка RC, `continue`. |
| 344–345 | Для закона высоты в пиры добавляется якорь как виртуальный сосед снизу/в колонне. |
| 347–352 | `_nearest_above_below_alt` с параметрами из аргументов. |
| 355–361 | Вертикальная скорость из `velocity_monitor` (если есть): `v_alt = -vz` (NED). |
| 363–371 | `sigma`, `_pwm_from_sigma`, итоговый throttle. |
| 373–374 | Отправка RC и пауза `CONTROL_DT`. |

## 11. Потоки данных (кратко)

1. **Инициализация:** N потоков `initialize_drone_parallel` + главный поток на барьере → все взведены и в POSHOLD с RC.
2. **Обмен:** один daemon-поток `exchange_loop` обновляет глобальное знание позиций для всех контроллеров и пишет CSV.
3. **Управление:** N потоков `_control_loop` читают якорь и пиров, считают RC с частотой 20 Гц.

Если нужно именно **каждая строка 1:1** без группировки, её можно сгенерировать скриптом из этого файла и исходника; по смыслу дублирование (например, 50 раз «`time.sleep(CONTROL_DT)` — пауза периода управления») мало добавляет к пониманию — здесь сохранена полнота логики и прямая привязка к номерам строк.
