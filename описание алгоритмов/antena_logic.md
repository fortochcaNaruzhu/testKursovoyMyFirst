# Алгоритм `antena_logic` (вертикальная «антенна» над якорем)

Файл реализации: `Drone_Swarm_Simulator_v2/scenarios/antena_logic.py`.

Цель сценария — запустить 4 дрона, выполнить взлёт и затем:

- удерживать всех дронов вблизи вертикальной оси над якорем по горизонтали \((x,y)\);
- по вертикали \(z\) построить равномерную «решётку» по высоте с шагом \(w\) **по локальному правилу ближайших соседей** (в духе `grid_antenna`/KA008), при этом **без назначения “мест” по ID**.

Управление выполняется через MAVLink `RC_OVERRIDE` (каналы roll/pitch/throttle/yaw).

---

## 1) Координаты и определения

- Используется локальная система NED из `LOCAL_POSITION_NED`:
  - \(x\) — North (м)
  - \(y\) — East (м)
  - \(z\) — Down (м), т.е. «вверх» соответствует уменьшению \(z\).
- Для удобства вертикальный «скаляр состояния» берётся как **высота над точкой взлёта**:

\[
a := -z
\]

То есть \(a\) растёт при наборе высоты.

### Common-frame по \(y\)

Симулятор SITL стартует каждый дрон со своим “home” со сдвигом по East, поэтому в сценарии применяется выравнивание:

\[
y_{common} = y_{local} + (id-1)\cdot 2.0
\]

Это делается, чтобы позиции всех дронов были в одной “общей” NED-рамке (как в `leader_forward_back` / `linear_chain2`).

---

## 2) Общая структура сценария

1. Параллельная инициализация 4 дронов:
   - подключение с HEARTBEAT timeout,
   - arm + takeoff,
   - переход в `POSHOLD`,
   - старт `rc_keepalive`,
   - запрос потоков `LOCAL_POSITION_NED` и `ATTITUDE`.
2. Запуск фонового цикла обмена позициями между контроллерами (`exchange_loop`):
   - каждый тик собираются `pos_common` всех дронов,
   - позиции рассылаются в `other_drones_positions` каждого контроллера,
   - публикуются позиции в 2D визуализатор (UDP) при наличии.
3. Запуск 4 управляющих потоков (по одному на дрон) с контроллером `rc_override`.
4. Логирование траекторий в формате “experiment dir” для ROS2 replay (см. раздел 6).

---

## 3) Горизонтальное удержание оси над якорем (PID по XY)

В каждом шаге управления для каждого дрона берётся положение якоря `anchor_id`:

\[
e_x = x^\dagger - x_i,\quad e_y = y^\dagger - y_i
\]

Где \((x^\dagger, y^\dagger)\) — координаты якоря, \((x_i,y_i)\) — координаты текущего дрона (в common-frame).

Затем:

- `pitch` формируется PID-регулятором от ошибки \(e_x\)
- `roll` формируется PID-регулятором от ошибки \(e_y\)
- `yaw` фиксируется нейтральным (`RC_NEUTRAL`)

Введены deadband для малых ошибок `XY_DEADBAND_M`, а выходы ограничены `XY_OUTPUT_LIMIT`.

---

## 4) Вертикальная логика (самораспределение по высоте по ближайшим соседям)

### 4.1 Поиск ближайших соседей “сверху” и “снизу”

Для текущего дрона со высотой \(a_i\) рассматриваются позиции остальных (из `other_drones_positions`), а также якорь (добавляется в список как “виртуальный сосед снизу”).

Для каждого видимого соседа \(j\) вычисляется:

\[
\Delta a_{ij} = a_j - a_i
\]

Из них выбираются минимальные положительные/отрицательные расстояния:

- \(d^+_i = \min\{\Delta a_{ij} : \Delta a_{ij} > 0\}\) — ближайший **выше**
- \(d^-_i = \min\{-\Delta a_{ij} : \Delta a_{ij} < 0\}\) — ближайший **ниже**

Если соседа нет:

- при отсутствии соседа сверху: \(d^+_i := R_{vis}\)
- при отсутствии соседа снизу: \(d^-_i := w\)

### 4.2 Сигма-функция и “bang-bang”

Используется скаляр:

\[
\sigma_i = v_{a,i} - \tanh(d^+_i) + \tanh(d^-_i)
\]

где \(v_{a,i}\) — текущая вертикальная скорость по высоте. В симуляторе `LOCAL_POSITION_NED` даёт `vz` (Down+), поэтому:

\[
v_{a,i} = -v_{z,i}
\]

Управление строится по знаку \(\sigma\) (bang-bang в духе `grid_antenna`):

\[
u_i = -\mathrm{sign}(\sigma_i)
\]

Далее \(u_i\) переводится в дельту PWM для throttle вокруг 1500:

- ограничение `Z_PWM_MAX`
- минимальный шаг `Z_PWM_MIN_STEP`

### 4.3 Якорь по высоте

Якорный дрон **не участвует в распределении по высоте**, а удерживает высоту \(a^\dagger = \texttt{TAKEOFF\_ALT\_M}\) PID-регулятором по throttle:

\[
e_a = a^\dagger - a_{anchor}
\]

## 5) Разрыв симметрии (bootstrap)

Если все дроны стартуют на одной высоте, то \(d^+\) и \(d^-\) у многих одинаковые, и алгоритм может “зависнуть” в симметрии.

Поэтому после взлёта применяется короткий bootstrap:

- на ~2 секунды неякорным дронам задаётся **разная** тяга (ступеньками по ID),
  чтобы создать небольшие отличия по высоте;
- затем включается основная логика ближайших соседей.

Bootstrap нужен только для старта и не является частью “теоремной” постановки — это практический механизм для SITL.

## 6) Логи для ROS2 replay (RViz2)

Сценарий пишет логи в директорию эксперимента в формате, который ожидает `replay/replay_rviz2.py`:

- `metadata.json`
- `drone_1.csv .. drone_4.csv`

CSV заголовок (строго):

```text
t,x,y,z,rx,ry,rz,hasCollision
```

Где:

- `t` — секунды от `START_TIME`
- `x,y,z` — позиции в **NED common-frame** (метры)
- `rx,ry,rz` — углы из `ATTITUDE` (рад)
- `hasCollision` — сейчас всегда `0`

### Выбор директории

- если задан `--experiment-dir`, пишется туда;
- иначе, если задан `--run-id`, пишется в `experiments/exp_<run-id>`;
- иначе — в `experiments/antena_logic_<timestamp>`.

### Частота записи

Параметр `--log-hz`:

- `> 0`: запись раз в \(1/\texttt{log\_hz}\) секунд,
- `0`: запись на каждом тике обменного цикла (≈50 Гц).

---

## 7) Параметры сценария (CLI)

Основные:

- `--duration` — длительность эксперимента (сек), `0` = до `Ctrl+C`
- `--anchor-id` — ID якорного дрона
- `--w` — целевой вертикальный шаг \(w\) (м)
- `--r-vis` — “видимость” по вертикали \(R_{vis}\) (м)
- `--xy-vis` — (если используется) горизонтальная фильтрация видимости для выбора соседей
- `--z-pwm-max`, `--z-pwm-min-step` — параметры bang-bang перевода \(\sigma\) в throttle PWM

Логирование:

- `--experiment-dir`
- `--run-id`
- `--log-hz`
